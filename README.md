# Order Book Data Processing System

A small, stateless FastAPI application that accepts one `.xlsx` workbook, processes only the eight configured columns from its first worksheet, creates a professional two-tab workbook, and provides a searchable/sortable browser preview.

## What it does

- Validates the exact eight required source columns.
- Keeps duplicates and ignores all unrelated source columns.
- Normalizes dates and `BagQty`; keeps identifier fields as text where possible.
- Warns about invalid dates and quantities instead of guessing values.
- Creates `Processed Data` (8 columns) and `Summary` (9 columns).
- Uses a `TODAY()` Excel formula for a dynamic delivery-day gap, including negative future gaps.
- Limits file size and row count, validates the XLSX container, uses random temporary names, and deletes downloads after delivery.

## Run locally

Python 3.11+ is required.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open `http://localhost:8000`.

## Run with Docker

```bash
docker compose up --build
```

Open `http://localhost:8000`. Stop with `docker compose down`.

## Test

```bash
pytest -q
```

## API

- `GET /health` → `{"status":"healthy"}`
- `POST /api/process` with multipart field `file`
- `GET /api/download/{file_id}`

Interactive API documentation is at `http://localhost:8000/docs`.

## Configuration

Copy `.env.example` values into your deployment environment. Environment variables are read at startup:

- `MAX_UPLOAD_MB` (default `15`)
- `MAX_ROWS` (default `100000`)
- `FILE_TTL_MINUTES` (default `30`)

## Low-cost cloud deployment

Deploy the included Dockerfile to Render, Railway, Fly.io, Google Cloud Run, Azure Container Apps, or another container host. Expose port `8000`; no database or persistent disk is required. For multiple production replicas, route each process/download sequence to the same replica or replace the short-lived local download store with an object store.

### Free Render deployment

1. Push this folder to a GitHub repository.
2. In Render, choose **New → Blueprint**.
3. Connect the repository and select its `render.yaml` file.
4. Confirm the `free` service plan and deploy.

The app will receive a public `onrender.com` address. Free services can sleep after inactivity; the first visit after sleep can take about a minute. Preview data remains in each user's browser, but an expired download must be regenerated by uploading the workbook again.

## Data note

Excel files that store identifiers as text retain leading zeros. Numeric cells with an all-zero Excel number format (for example `000000`) are also reconstructed with leading zeros. If a source workbook stored `001245` as the number `1245` with a general format, the missing zeros cannot be recovered.
